IrieBook Authoring Guide

How to write in Google Docs so the EPUB and PDF come out exactly as you wish.

When IrieBook syncs your Google Doc, it transforms the document into the final ebook. This guide describes every convention you can rely on: what to type in the doc, and what effect it produces in the output.

The golden rule: Use Google Docs' built-in heading styles (Heading 1 / 2 / 3) and italics. Manual formatting (fonts, sizes, colours) is ignored.

1. How the Document Becomes an Ebook

The journey has four steps:

  1. Google Doc export. IrieBook exports your document through the Google Drive API. Heading styles and italics are captured along with the text.
  2. Document shaping. IrieBook's engine renumbers chapters, inserts scene breaks, builds the dedication and copyright pages, and tidies whitespace.
  3. EPUB forging. Pandoc wraps the document with the bundled stylesheet (default.css) into a valid EPUB.
  4. Kindle sapphire. Calibre converts the EPUB to AZW3.

2. Chapter Headings

Convention: Write every chapter heading as a [H2]. IrieBook promotes these to top-level chapters in the output: centered, uppercase, bold, each starting on a new page.

Numbered chapters

Any heading whose last word is an Arabic numeral is a numbered chapter. The number is renumbered sequentially starting at 1 in the output, so gaps or duplicates in the source are smoothed away.

The "prefix" is everything before the trailing number. All headings with the same prefix form a series and are renumbered independently:

Google DocsEbook output
Chapter 1Chapter 1
Capitolul 5Capitolul 2
Epilog 3Epilog 1
421
  • Chapter, Capitolul, and Epilog are all prefixes.
  • 42 has no prefix, so it belongs to the empty-prefix series and becomes 1.
  • The first spelling IrieBook sees for a prefix becomes the canonical name for that series.

Roman numerals are not recognised. Chapter IX is treated as plain text. Use Arabic digits (Chapter 9) if you want numbering.

Non-numbered chapters

A heading whose last word is not an Arabic numeral is preserved verbatim. Prologue, Epilogue, Introduction, and Prelude all render as-is in the ebook.

Typo tolerance between prefixes

Prefixes are matched case-insensitively with an edit distance of up to {{FUZZY_PREFIX_MAX_EDIT_DISTANCE}} characters. If you write Capitol 1 in one place and Capitolul 5 in another, IrieBook treats them as the same series and renumbers them consistently using the first spelling encountered.

Other heading levels

  • [H1] is for front matter and structural breaks. IrieBook automatically strips the document title that Google Docs injects as a tab heading.
  • [H3] is an ordinary in-chapter sub-section header, unless its entire content is italic, in which case it becomes a dedication.

Google Docs tab heading caveat: Google Docs can export an automatic Tab heading before the real manuscript. IrieBook strips the English Tab heading today. The Romanian label Fila is not stripped yet, so it may appear incorrectly in the generated book until that language-specific cleanup is fixed.

A regular H3 is not promoted to a chapter, does not start a new page, and does not get IrieBook-specific HTML. Internally it stays as ### Heading text, so Pandoc and the reading app render it as a normal third-level heading inside the current chapter.

In your Google Doc

[H2] Author's Note

This book borrows a few words from Romanian folklore.

[H3] Romanian Terms

Strigoi refers to a restless spirit in old village stories.

Rendered in the ebook

Author's Note

This book borrows a few words from Romanian folklore.

Romanian Terms

Strigoi refers to a restless spirit in old village stories.

3. Chapter Titles with Subtitles

A subtitle renders as an italic, centered paragraph tucked just under the heading. Separate the title from the subtitle on the same line with a dash.

In your Google Doc

[H2] Chapter 1 - The Beginning

Rendered in the ebook

Chapter 1

The Beginning

The first paragraph begins here...

Supported dash separators

SeparatorIn Google Docs write...
En dash with spaces[H2] Chapter 1 – The Beginning
Em dash with spaces[H2] Chapter 1 — The Beginning
Hyphen with spaces[H2] Chapter 1 - The Beginning
Hyphen, no spaces[H2] Chapter1-The Beginning

Space-separated subtitle

If the heading is exactly three or more words and the second word is an Arabic number, the first two words become the title and the rest becomes the subtitle. For [H2] Chapter 1 The Beginning, the title becomes Chapter 1 and the subtitle becomes The Beginning.

Escaped dashes

Backslash-escaped dashes, a common Google Docs export artefact, are cleaned up automatically. [H2] Capitolul 1 \- Bianca becomes Capitolul 1 with subtitle Bianca.

Empty subtitle

A dash with nothing after it is dropped. [H2] Chapter 1 - becomes just Chapter 1.

Sentence guard

If the text after the dash contains sentence punctuation (period, comma, exclamation, question mark), the whole line is kept as the title and no subtitle is emitted. This stops a paragraph accidentally fused onto a heading from being misread as a subtitle.

Non-numbered chapter with subtitle

Prologues and epilogues can carry subtitles too, via any of the dash forms: [H2] Prologue - The Beginning or [H2] Epilogue - Final Words.

4. Scene Breaks

A scene break renders as a centered ornament, the floral heart glyph ❦, sitting between two prose passages.

Explicit marker: to force a scene break from Google Docs, put a single # on its own paragraph line:

In your Google Doc

The first scene ends.

#

The next scene begins.

Rendered in the ebook

The first scene ends.

❦

The next scene begins.

Google Docs exports that line as \# in Markdown. IrieBook recognizes that escaped export form. A raw Markdown # is preserved as Markdown, so existing Markdown headings and text are not changed.

Automatic scene breaks still exist. IrieBook can also decide for you, based on the rhythm of the prose:

  • A blank line is promoted to a scene break only when there are at least {{CHUNKY_PARAGRAPH_THRESHOLD}} consecutive paragraph lines immediately before it and at least {{CHUNKY_PARAGRAPH_THRESHOLD}} consecutive paragraph lines immediately after it.
  • Both neighbours must be ordinary prose paragraphs, not italics and not headings.
  • Scene breaks are suppressed next to any heading, subtitle, or italic line, so chapter openings, dedications, and poems are never split by an ornament.

In your Google Doc

Ten or more prose paragraphs...

[blank line]

Ten or more prose paragraphs...

Rendered in the ebook

The scene draws to a quiet close.

One last thought lingers in the room.

❦

The next scene opens under a different sky.

Everything has shifted, softly but surely.

In practice: use a standalone # in Google Docs when you want full control. Long, chunky scenes separated by a blank line may still get a ❦ automatically. Short passages, poems, and dialogue clusters do not.

5. Dedications

A dedication becomes its own centered, unnumbered page, vertically centered on the screen, in italics, and hidden from the table of contents.

Convention: write the dedication as a [H3] whose entire content is italic.

In your Google Doc

[H3] For my family,
with all my heart

[H2] Chapter 1

Rendered in the ebook

For my family,
with all my heart

Chapter 1

The story begins...

Rules:

  • The whole heading content must be italic. A partially italic heading like [H3] Some *italic* word is treated as an ordinary H3, not a dedication.
  • Consecutive dedication lines, optionally separated by blank lines, are merged into a single dedication page with multiple paragraphs.

6. Italic Lines and Poetry

A paragraph line in italics (Google Docs italics) is detected as an italic line and rendered distinctly. Importantly, italic lines never trigger scene breaks before or after them. This protects multi-stanza poems from being sliced apart.

In your Google Doc

The river runs beneath the hill,
and carries every dream it will.

Apply Google Docs italics to each poem line.

Rendered in the ebook

The river runs beneath the hill,

and carries every dream it will.

Blank lines between italic lines are safe. No ornament will appear among them.

7. Dialogue and Quote Curling

Convention: always use double quotes for dialogue. IrieBook converts them automatically into proper typographic quotes (left and right).

In your Google Doc

"Hello," she said.

Rendered in the ebook

“Hello,” she said.

Already-curly quotes are also accepted. IrieBook will normalise them.

The curler is a state machine: it alternates opening and closing, so every pair balances. Double quotes must be even in number. An odd count is a validation error and blocks publication.

Formatting (italics, bold) inside quotes is left untouched by the curler.

Single quotes for dialogue are forbidden. See Apostrophes.

8. Apostrophes

Legitimate apostrophes (straight ') are auto-curled. Dialogue single quotes are rejected as errors.

CaseExampleResult
Contractionsit's, can't, we'recurled
PossessivesJohn's, James'curled
Abbreviated years'70s, '80scurled
Omitted letters'cause, 'til, 'emcurled
Romanian elisiondracu', intr'curled

Never use single quotes to wrap spoken dialogue. Use double quotes for dialogue instead. The validator lists every offending line, column, and context so you can find them fast.

9. Whitespace (Cleaned Automatically)

You can be a little messy. IrieBook tidies whitespace before shaping:

IssueWhat happens
Multiple consecutive spacesCollapsed to a single space
TabsConverted to a single space, then collapsed
2+ blank lines in a rowCapped at a single blank line
Leading / trailing spaces on a lineTrimmed
Windows line endingsNormalised to Unix

These run before the markdown shaping, so the scene-break threshold counts clean paragraphs.

10. Word Replacement

For case-sensitive, whole-word find/replace, typically to add diacritics the manuscript is missing, use Edit Metadata in the Irie app and add a replacement pair:

Irie metadata editor

Source: Rene
Target: René

Do not hand-write replacement pairs into metadata.yaml. The editor owns this feature; the storage format may move behind the scenes.

Behaviour:

  • Whole word only. The standalone word Rene changes, but the inside of Irene is untouched.
  • Case-sensitive. Rene matches Rene, nothing else.
  • Automatic uppercase variant. If the target differs from the source when uppercased, the ALL-CAPS form is replaced too, so RENE becomes RENÉ.
  • Word boundaries include hyphens, so Andre-Rene becomes Andre-René.

Word replacement runs last in the pipeline, after quote curling and whitespace trimming.

11. Special Characters and Romanian Diacritics

  • UTF-8 BOM is stripped on read. Files Google Docs or Windows export with a leading byte-order mark are cleaned; output is always written without a BOM.

12. Front Matter Pages (Auto-generated)

Copyright page

Trigger: place a copyright.txt file in the book folder, next to book.md. If the file is absent, no copyright page is generated.

The page is built from the file's contents plus your metadata:

  • The owner line: the copyright symbol, the current year, and the author.
  • The rights field from metadata, with any leading copyright-year prefix stripped.
  • The full contents of copyright.txt as the disclaimer block.
  • The ISBN / identifier, when present.
  • The IrieBook revision stamp, when published from a git repo.

When a copyright.txt exists, Pandoc's own auto-generated rights line is suppressed so there is no duplicate.

metadata.yaml

title: Moonlit Blood
author: Jane Doe
rights: All rights reserved.
identifier:
  - scheme: ISBN-13
    text: 978-1-23456-789-0

copyright.txt

No part of this publication may be reproduced,
distributed, or transmitted in any form without the prior written
permission of the author.

Rendered copyright page

© 2025 Jane Doe. All rights reserved.

No part of this publication may be reproduced, distributed, or transmitted in any form without the prior written permission of the author.

ISBN-13: 978-1-23456-789-0

Previous-books page (series recap)

Trigger: set belongs-to-collection and group-position in metadata.yaml. The page lists every earlier book in the same collection found in your workspace, sorted ascending.

title: Moonlit Blood
author: Jane Doe
belongs-to-collection: Night Garden
group-position: 3

A previous-books-template.md file is auto-created in the book folder on first run. Edit it to customise the layout. It uses Mustache-style placeholders inside a {{#books}} ... {{/books}} block:

# Also in the Night Garden series

{{#books}}
{{roman}}. {{title}}
Book {{position}} by {{author}}

{{/books}}
PlaceholderMeaning
{{roman}}Roman numeral of the book's position (I, II, III ...)
{{position}}Arabic position number
{{title}}Book title
{{author}}Book author

Title page

The title page is generated by Pandoc from your metadata. You do not author it in the document. Two metadata fields can add series information above the title:

  • belongs-to-collection + group-position — when both are set, a row of stars equal to the book's position and the series name are injected above the title.

metadata.yaml

title: Moonlit Blood
author: Jane Doe
belongs-to-collection: Night Garden
group-position: 3

Rendered title page

★ ★ ★
Night Garden

Moonlit Blood

Jane Doe

13. metadata.yaml Example

The metadata.yaml file sits in the book folder next to book.md. It may be wrapped in --- frontmatter delimiters or be plain YAML. Both work.

Editable in Irie: Title, author, series name, series position, and word replacements can all be edited directly in the Irie app. Click Edit Metadata on the book. Word replacements are an editor feature; do not hand-author them in metadata.yaml.

metadata.yaml

title: Moonlit Blood
author: Jane Doe
language: ro-RO
rights: All Rights Reserved
cover-image: cover.jpg
belongs-to-collection: Night Garden
group-position: 3
identifier:
  - scheme: ISBN-13
    text: 978-1-23456-789-0

title and author are required and must be non-empty. They drive the title page, copyright owner line, and output filename.

language defaults to ro-RO, cover-image defaults to cover.jpg, and rights defaults to the current year plus "All Rights Reserved" when absent.

Set belongs-to-collection and group-position together to enable the previous-books page and title-page series banner. identifier entries, such as ISBN-13, appear on the copyright page as scheme: text.

14. config.json Field Reference

Configuration is read from two places: ~/.iriebook/config.json for machine-wide defaults, then a workspace-local config.json in the library root. The local file wins.

Word analysis

  • word_analysis.excluded_words — array of strings filtered out of word-frequency analysis. A default set of Romanian stopwords is always present; local words are merged in, not replacing the defaults.

PDF print settings (under pdf)

To change PDF output, create or edit this file in your book library folder:

config.json

{
  "pdf": {
    "enabled": true,
    "page_width": "5.5in",
    "page_height": "8.5in",
    "font_family": "Liberation Serif",
    "font_size": "11pt",
    "line_spacing": 1.2,
    "inner_margin": "2.2cm",
    "outer_margin": "1.8cm",
    "top_margin": "1.8cm",
    "bottom_margin": "1.8cm",
    "justified": true,
    "pdf_engine": "xelatex"
  }
}

Use inch values like 5.5in, metric values like 2.2cm, or point values like 11pt where shown. Set enabled to false if you only want EPUB/AZW3 output.

At publish time, a page-size profile can override the page dimensions: Digest is 5.5in by 8.5in; A5 is 148 by 210 mm.

15. Front-matter Assembly Order

Front matter is assembled in this fixed order:

  1. Copyright page (if copyright.txt exists)
  2. Previous-books page (if the book is part of a series with earlier entries)
  3. Manuscript body (book.md)

In the EPUB spine, the flow becomes: title page, then copyright, then table of contents, then dedication, then body.

16. Validation Gates (What Blocks Publication)

Validation runs as a hard gate before any output is written. If it fails, the pipeline reports a validation_failure result and writes no files.

The gate fails when:

  • Double quotes are unbalanced (odd count). The last offender's line, column, and context are reported.
  • Single quotes are used as dialogue. Every offender is listed.

Everything else (whitespace, BOM, quote curling, word replacement) is non-blocking and applied silently.
